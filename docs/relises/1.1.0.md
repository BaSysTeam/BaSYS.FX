1. Register queries now support boundaries based on a date or an operation moment. Use `beforeMoment`, `upToMoment`, `fromMoment` and `afterMoment` to mark the start or end of a period, and `moment(header, metaObject)` to build a moment from the operation date, metadata object and number; the metadata object is required, and an empty number (`undefined`, `null`, `''` or `0`) is stored as `null`. A date boundary is written as local time to the whole second, with `metaObject` and `number` equal to `null`. `column` names another date column and is accepted only with a date, while `excludeOwn` is sent as `true`, `false`, or `null` when omitted so the server chooses the default. Each call appends one entry to `boundaries` and leaves the condition, parameters and filters unchanged; the boundary takes effect only when the server supports the field.

2. Scripts can now round numbers with `round(value, digits = 0)`, using the canonical decimal digits shown by `String(value)` and rounding ties away from zero: `round(1.005, 2)` returns `1.01`, and `round(-1.5)` returns `-2`. Precision must be an integer from `-308` to `324`; negative values round places before the decimal point. Only primitive numbers are accepted: invalid argument types throw `TypeError`, and invalid numeric precision throws `RangeError`. The result is a number without trailing zeros and retains IEEE 754 limits; valid precision preserves `NaN` and infinities, and any zero result becomes positive zero. `formatNumber` and numeric `format` now use the same decimal rule, with display precision from `0` to `100` (default `2`), and pad decimal text directly. This changes earlier formatting results: `formatNumber(1.005)` returns `"1.01"` instead of `"1.00"`, high-precision `0.1` no longer exposes binary expansion digits, and `formatNumber(-0.004)` returns `"0.00"` instead of `"-0.00"`. Finite exponential inputs are rendered as plain decimal text, and non-finite values remain whole `NaN`, `Infinity`, or `-Infinity` tokens. Existing masks, grouping and custom separators remain supported.

3. Scripts now preserve operand grouping when composing SELECT conditions with `whereAnd` and `whereOr`: each call wraps both the accumulated condition and the new fragment in parentheses. This is a breaking change: `where('a').whereOr('b').whereAnd('c')` previously produced `a or b and c`, meaning `a OR (b AND c)`, and now produces `((a) or (b)) and (c)`, meaning `(a OR b) AND c`. To preserve the former meaning, use `where('a').whereOr('b AND c')`. Review mixed condition chains before upgrading. The first fragment remains unchanged, `where` still replaces the condition, and `where('')` clears it. Composition guarantees apply to non-empty SQL fragment strings; no input validation or empty-fragment skipping is added.

4. Scripts can now sort an in-memory `DataTable` by multiple columns with `orderBy('number, period desc')` or `orderBy(['number', 'period desc'])`; TypeScript also accepts readonly arrays and string/array unions. Criteria apply from left to right, default to ascending, and accept case-insensitive `asc`/`desc`. Sorting returns the same table, preserves the row array and row objects, and keeps the input order of complete ties. Use columns with a consistent runtime value type: numbers compare numerically, strings use case-sensitive JavaScript order, booleans sort `false` before `true`, and valid `Date` objects compare chronologically. `null`, `undefined`, `NaN` and invalid dates are treated as equal missing values and placed last in either direction. Column names match exactly, including case and literal punctuation; SQL expressions, identifier unquoting and nested property paths are not interpreted. A blank string or empty array leaves the order unchanged. Empty list segments (including trailing commas), malformed criteria and unknown columns throw before sorting, leaving the table unchanged. Existing comparator calls remain supported for custom ordering; this change does not affect `SelectQueryBuilder.orderBy`.
